# Как развивать документацию

## Добавление страницы

1. Создайте Markdown-файл в `guide/`, `examples/` или `reference/`.
2. Добавьте ссылку в `themeConfig.sidebar` файла `.vitepress/config.mjs`.
3. Запустите сайт и проверьте страницу.
4. Выполните сборку: она также проверяет внутренние ссылки.

## Шаблон описания метода

Используйте следующую структуру при добавлении справочной страницы:

- **Назначение** — какую задачу решает метод.
- **Сигнатура** — параметры и возвращаемый тип из исходников.
- **Авторизация** — нужен ли токен аккаунта или медиатокен.
- **Пример** — минимальный сценарий без настоящих секретов.
- **Результат** — пояснение важных полей.
- **Ошибки и ограничения** — известные особенности.
- **Проверка** — источник сведений и версия библиотеки.

::: warning Достоверность
Не помечайте метод проверенным только потому, что он есть в исходниках.
Разделяйте подтверждённое запросами поведение и предположения.
:::

## Что хранить вручную

Руководства и сценарии использования. Полный справочник типов лучше генерировать
из TypeScript и JSDoc командой `npm --prefix docs run api`.
Редактируйте комментарии в `src/`, а не страницы `reference/generated/`.

## Локальная сборка для разработчиков SDK

Пользователям достаточно `npm install anixartjs`. Если вы изменяете саму библиотеку,
установите зависимости и соберите её из корня репозитория:

```sh
npm install
npx tsc
```

В локальных скриптах из папки `examples/` используйте `require("../dist/index")`,
чтобы проверять собственные изменения, а не установленную версию npm.
Например, после сборки запустите `node examples/searchReleases.js Наруто`.
